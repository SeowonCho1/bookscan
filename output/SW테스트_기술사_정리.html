요약 정리 구조 기반 테스트 — 제어 흐름 / 데이터 흐름

제어 흐름 테스트 (Control Flow Testing)

프로그램의 제어 흐름을 CFG(제어 흐름 그래프)로 시각화하고, 노드(연산/조건)와 엣지(흐름)를 분석하여 모든 실행 경로를 검증하는 화이트박스 기법

절차:

코드 분석
→
CFG 작성
→
커버리지 목표 설정
→
TC 설계
→
실행·수집
→
미테스트 경로 보완

McCabe 순환복잡도: V(G) = E - N + 2 → 독립 경로 수 = 최소 TC 수

데이터 흐름 테스트 (Data Flow Testing)

변수의 DEF(정의) → USE(사용) 경로를 추적하여 데이터 아노말리(미사용 변수, 잘못된 참조 등)를 탐지하는 화이트박스 기법
레이블의미예시
def변수에 값 할당(정의)int x = 10;
c-use연산식에서 사용z = x + y;
p-use조건식에서 사용if (x > 5)
kill변수 소멸함수 종료 시
du-pathdef → c/p-use 경로def x → p-use x

데이터 흐름 커버리지 기준 (약 → 강)

all-defs < all-c-uses < all-p-uses < all-uses < all-du-paths

all-defs    : 모든 변수 정의가 최소 1번 사용
all-c-uses  : 모든 연산식(C-USE) 경로 포함
all-p-uses  : 모든 조건식(P-USE) 경로 포함
all-uses    : C-USE + P-USE 모두 포함
all-du-paths: 모든 DEF→USE 경로 (루프 최대 1회)

데이터 흐름 테스트 (Data Flow Testing)
DEF-USE-KILL 레이블 체계, du-path 개념, all-defs~all-du-paths 커버리지 기준이 핵심. 제어 흐름 테스트와 비교 문제로 2교시 출제 가능성 높음. 139회에서 화이트박스 비교가 나왔고, 이를 심화한 DFT는 다음 회차 출제 유력.
⭐⭐⭐ 예상 토픽 2위
탐색적 테스트 (Exploratory Testing)
차·박·노·디 4요소, TC기반 테스트와 비교, 세션 기반 수행 절차. 1교시 단답으로 출제 가능. 139회·137회 모두 명세기반/구조기반 중심이었으므로 경험기반 테스트 차례 도래.
⭐⭐⭐ 예상 토픽 3위

⭐⭐ 예상 토픽 4위
인수 테스트 유형 (6가지)
사·운·계·규(공식) + 알파·베타(비공식). 1교시 단답으로 자주 나오는 유형. 공식/비공식 분류 축과 각 유형의 수행 주체 명확히 암기 필요.
⭐⭐ 예상 토픽 5위
스모크·새너티·Cursory 비교 + AI 테스트
4가지 즉흥성 테스트 수행 시점·목적 차이. AI 신뢰성 검증(CAT, 메타모픽 테스트, 뉴런 커버리지)은 최신 트렌드로 137회에서 나왔으나 심화 출제 가능.

1. 동적·유연한 품질 검증 기법, 탐색적 테스트의 개요

기존 TC기반:  계획 → 설계 → 구현 → 실행  (순차)

2교시 예상답안 (25점) 데이터 흐름 테스트(Data Flow Testing)에 대하여 설명하시오.

1. 변수의 생애주기 기반 결함 탐색, 데이터 흐름 테스트의 개요

가. 정의

프로그램 내 변수의 정의(DEF)와 사용(USE) 간의 관계를 분석하여 데이터 아노말리(Data Flow Anomaly)를 탐지하는 화이트박스 구조 기반 테스트 기법

나. 필요성

미사용 변수·잘못된 변수 참조·초기화 오류 등 제어 흐름 테스트로 검출하기 어려운 데이터 관련 논리 오류를 탐지하기 위해 필요

2. 핵심 개념 — 변수 레이블 체계

레이블의미예시
def변수에 값 할당(정의)int x = 10;
c-use연산식에서 사용z = x + y;
p-use조건식에서 사용if (x > 5)
kill변수 소멸(메모리 해제)함수 종료 시
du-pathDEF → c/p-USE 까지의 경로def x → p-use x
변수 x의 생애주기 흐름:
  ① def x = 5  →  ② if(x > 0)    →  ③ y = x + 10
                         [p-use x]           [c-use x]
                              │
                              ▼
                         ④ kill x (함수 종료)

  du-path: ①→②(p-use), ①→③(c-use)

3. 데이터 흐름 커버리지 기준 (약 → 강)

all-defs < all-c-uses < all-p-uses < all-uses < all-du-paths
커버리지 기준설명
all-defs모든 변수 정의(DEF)가 최소 1번 사용되도록 보장
all-c-uses모든 DEF에서 도달 가능한 모든 연산식(C-USE) 실행
all-p-uses모든 DEF에서 도달 가능한 모든 조건식(P-USE) 실행
all-usesall-c-uses + all-p-uses 결합 (연산+조건 모두)
all-du-paths모든 DEF → USE 경로 포함 (루프 최대 1회 반복)

4. CFT vs DFT 비교

구분제어 흐름 테스트 (CFT)데이터 흐름 테스트 (DFT)
분석 대상코드 실행 경로·분기변수의 DEF-USE 관계
활용 도구CFG (제어 흐름 그래프)DFG (데이터 흐름 그래프)
검출 결함경로 오류, 분기 누락미사용 변수, 잘못된 참조
커버리지구문·분기·경로 커버리지all-defs ~ all-du-paths
관계기반(선행) 기법CFT 위에서 확장 수행

5. 커버리지 산출 사례

x = a + 2;     ← def x, c-use a
y = 24;        ← def y
if (x > 12)   ← p-use x
    y = 30;    ← def y (재정의)
z = x + y;    ← def z, c-use x, c-use y

[all-defs 기준]
  정의된 변수: x, y, z → 모두 1회 이상 사용
  커버리지 = 3/3 = 100%

6. 적용 시 고려사항 (결론)

고려사항내용
CFT와 병행DFT는 CFG를 기반으로 확장하므로 제어 흐름 분석 선행 필수
루프 처리all-du-paths 적용 시 루프 최대 1회 반복으로 제한 (경로 폭발 방지)
